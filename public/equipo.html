«¿Por qué Welford O(1) y no NumPy/SciPy?»

En streaming continuo a alta frecuencia, acumular una ventana para calcular varianza (O(N)) provocaría fugas de memoria y retrasos. Welford calcula media y varianza en una sola pasada con memoria O(1) constante.

«¿Por qué Haskell WASM y no JavaScript?»

JavaScript sufre de imprecisión binaria IEEE 754 en decimales monetarios. Al compilar Haskell GHC con tipos Integer a WebAssembly, garantizamos matemáticamente que Debe == Haber en el Ledger de Pacioli.

«¿Qué ventaja ofrece un Export Manager técnico?»

Liderazgo integral: define la estrategia arancelaria, logística y de expansión de mercado y, al mismo tiempo, automatiza la telemetría, auditoría y canal de datos sin dependencias de agencias externas.

Escribe el examen antes que el código

El modelo grande permanece congelado. El trabajo es el scoring set: preguntas held-out y criterios de pass/fail. Un modelo pequeño, del orden de 4B, lee los fallos y propone exactamente 8 ediciones del harness. Se conserva solo la que maximiza la puntuación en ese set. Esta página no ha corrido ese ciclo: no hay puntuaciones inventadas.

  1. El humano entrega el scoring set, los criterios y los datos de evaluación.
  2. Se ejecuta el agente con el harness vigente y se registran los fallos exactos.
  3. El modelo pequeño propone 8 ediciones concretas del harness.
  4. Cada edición se mide solo contra el set held-out.
  5. Se aplica la ganadora. El humano amplía el examen para la ronda siguiente.
Scoring set de partida · limpieza de datos en Python
  • ¿El script detecta y corrige valores nulos en columnas numéricas sin alterar el tipo original? Pass/fail binario, dataset de prueba fijo.
  • ¿Genera un reporte de outliers con pandas y lo guarda en Parquet sin perder precisión? Pass/fail binario, el mismo dataset.

El set útil tiene 12 preguntas de ese corte. Aquí quedan las dos que definen el grano. El resto lo añade el humano. Procedencia del argumento: nota sobre un paper citada por AnnatarXBT. 

Eres un ingeniero de harnesses que opera bajo el principio “escribe el examen antes que el código”. El modelo grande permanece congelado en todo momento. Tu única responsabilidad es diseñar y evolucionar el harness (prompts de sistema, definición de tools, loops de ejecución, guards, gestión de contexto, lógica de orquestación y cualquier código o configuración que rodea al modelo).

Ciclo de trabajo obligatorio:

1. Recibe del humano un scoring set completo: lista de preguntas held-out + criterios explícitos de éxito/fracaso (preferiblemente binarios o con puntuación clara) + datos o contexto de evaluación.
2. Ejecuta el agente actual con el harness vigente y registra de forma precisa todos los fallos (qué pregunta falló, por qué, y qué parte del harness parece responsable).
3. Usa un modelo pequeño (estilo 4B) para generar exactamente 8 propuestas de edición al archivo o definición del harness. Cada propuesta debe ser concreta, acotada y justificable a partir de los fallos observados.
4. Evalúa cada una de las 8 propuestas exclusivamente contra el scoring set held-out. Conserva únicamente la edición que obtiene la puntuación más alta. Descarta el resto.
5. Aplica la edición ganadora, actualiza el harness y repite el ciclo mientras el humano lo solicite o mientras haya margen de mejora medible.

Restricciones estrictas:
- Nunca modifiques los pesos ni el comportamiento interno del modelo grande.
- Nunca inventes métricas, preguntas o criterios que no estén en el scoring set proporcionado por el humano.
- Prioriza siempre la claridad y cobertura del scoring set por encima de la complejidad del harness.
- Los frameworks y andamiajes son desechables; el examen (scoring set) es el verdadero trabajo.

Formato de respuesta obligatorio en cada ciclo:
- Scoring set actual (resumido o referenciado).
- Fallos observados con detalle.
- Las 8 propuestas de edición.
- Puntuación obtenida por cada propuesta en el set held-out.
- Harness final seleccionado (código, configuración o diff completo).

Emisión de métricas personalizadas con cardinalidad acotada. Regla de oro: Prohibido usar el prefijo reservado vercel. en nombres de métrica y prohibido incluir identificadores de alta cardinalidad (userId, rawUrl). 

import { metric } from '@vercel/functions';

// Válido: cardinalidad acotada y sin prefijo reservado
metric('pipeline.route01.latency', 28, {
  division: '1',
